## 1. ЧТО ТАКОЕ LIVEOPS

Всё, что происходит **после** релиза:
- Обновления контента
- События
- Сезоны
- Балансные правки
- Баг-фиксы

Цель: удерживать игроков и поддерживать доход.

---

## 2. ЦИКЛ ОБНОВЛЕНИЯ

### Каденция (рекомендуется)

```
Bug-fix патч         — по необходимости
Балансный патч       — раз в 1-2 недели
Контентный апдейт    — раз в 2-4 недели
Сезон / событие      — раз в 4-8 недель
Major update         — раз в 2-3 месяца
```

### Из Merge Farm

v1.0 → v1.1 (через 2-4 недели): новый контент, баланс, баги.

## 3. ВЕРСИОНИРОВАНИЕ

### Semantic Versioning (с адаптацией)

```
MAJOR.MINOR.PATCH
   1  .  0  .  0

MAJOR — большое обновление (новые системы)
MINOR — контент (новые tier'ы, события)
PATCH — баги, баланс
```

### Build / version

```ts
export const VERSION = '1.2.3';
export const BUILD = '2026-07-14-a1b2';
```

### В UI

Показывать только MAJOR.MINOR. Build — для разработчика.

## 5. ОБНОВЛЕНИЯ КОНТЕНТА

### v1.1: первый апдейт (через 2-4 недели)

#### Что добавить

```
✓ 2-3 новых tier'а овощей
✓ 1 новый буст
✓ 1 новое событие (на неделю)
✓ 5-10 новых достижений
```

❌ Новые системы (IAP, мультиплеер)

❌ Изменение core loop  
❌ Удаление контента

## 6. СОБЫТИЯ (EVENTS)

### Длительность

```
Mini-event:     3-7 дней
Major event:    7-14 дней
Season:         30-60 дней
```

### Структура события

```
1. Анонс (за 1-3 дня)
2. Старт (все получают уведомление)
3. Событийный контент (спец. валюта, предметы)
4. Награды (накопительные + за этапы)
5. Финал (последний шанс)
6. Подведение итогов
```

### Пример

```
Событие "Урожайный месяц"
- Длительность: 14 дней
- Спец. валюта: "Тыквенные семечки"
- Контент: 5 новых овощей
- Награды: легендарный питомец за 100 семечек
- Буст: x2 к тыквенным merge на время события
```

### Что НЕ делать

❌ Событие без отличий от обычной игры  
❌ Слишком сложные условия (игрок не понимает)  
❌ Награды, которые не стоят усилий  
❌ Событие без анонса (никто не знает)

## 7. БАЛАНСНЫЕ ПРАВКИ

### Когда

- Игроки застревают (об этом говорят)
- Метрики показывают дисбаланс
- Retention падает

### Как

1. Собрать данные
2. Понять причину
3. Сделать минимальную правку
4. Следить за метриками 7 дней
5. Откатить если хуже

### Что НЕ делать

❌ Менять баланс без данных  
❌ Менять несколько параметров сразу  
❌ Менять баланс в середине события  
❌ Делать резкие изменения (x10 или /10)

### Изменения

```
Income rate:           ±20%
Cost growth:           ±0.1 (1.3 → 1.4)
Rare chance:           ±0.5% (2% → 2.5%)
Offline cap:           ±1 час
```

## 8. БАГ-ФИКСЫ

### Приоритеты

```
P0 Critical — игра не запускается
P1 High     — критическая функция не работает
P2 Medium   — мешает, но можно играть
P3 Low      — косметика
```

### SLA

```
P0: hotfix в течение 24 часов
P1: hotfix в течение 1 недели
P2: в ближайшем плановом обновлении
P3: когда будет время
```

### Hotfix процесс

1. Получить баг (support, analytics, тестирование)
2. Воспроизвести
3. Исправить
4. Протестировать
5. Залить на Yandex
6. Дождаться модерации (1-3 дня)
7. Опубликовать

### Postmortem

После каждого P0/P1:
- Что случилось
- Почему
- Как предотвратить
- Добавить в STUDIO_MEMORY

## 10. МЕТРИКИ LIVEOPS

### Здоровье проекта

```
DAU trend:             растёт / стабильно / падает
D1 retention trend:    стабильно > 30%
D7 retention trend:    стабильно > 10%
ARPDAU trend:          стабильно или растёт
Crash rate:            < 1%
```

### Успех обновления

```
+5-10% DAU через неделю
+2-5% D7 retention
+10-20% revenue
```

### Провал обновления

```
-10% DAU
-5% D7 retention
Много негативных отзывов
```

### Если провал

1. Проанализировать что пошло не так
2. Откатить (если возможно)
3. Компенсировать игрокам (награда)
4. Postmortem
5. Не повторять

---

## 11. ANTI-PATTERNS

❌ Слишком частые обновления (выгорание команды)  
❌ Слишком редкие обновления (забывание)  
❌ Большие обновления (высокий риск багов)  
❌ Удаление контента (loses trust)  
❌ Изменение core loop (retention drop)  
❌ Pay-to-win новый контент (paywall)  
❌ Эксклюзивный контент только за IAP
