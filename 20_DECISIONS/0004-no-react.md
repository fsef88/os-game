# 0004 — Не использовать React

**Дата:** 2026-07-14
**Статус:** Принято

## Контекст

React — самый популярный фреймворк для UI. Возникает вопрос: использовать ли его в играх студии.

## Решение

**Не использовать React** в играх студии. Использовать чистый DOM + TypeScript.

## Альтернативы

- **React** — большая экосистема, много разработчиков знают
- **Vue** — проще React, но не нужен
- **Svelte** — компилируется, но ИИ хуже пишет
- **Lit** — web components, слишком нишево
- **Чистый DOM** — никаких зависимостей, максимальный контроль

## Почему НЕ React

1. **ИИ хуже пишет React**, чем vanilla DOM — нужны JSX, hooks, эффекты, что увеличивает вероятность багов
2. **Больше зависимостей** — npm install тяжелее, bundle больше
3. **Overhead для игр** — virtual DOM не нужен для 50-200 элементов
4. **Сложнее править через ИИ** — изменение одного компонента может сломать другие
5. **Лишний слой абстракции** — игре не нужен state management в React-style

## Последствия

✅ Меньше зависимостей (только typescript + vite)
✅ Меньший bundle (на 30-50% меньше, чем React)
✅ ИИ быстрее и точнее пишет код
✅ Проще отлаживать
✅ Быстрее старт dev-server

❌ Меньше готовых компонентов (делаем сами — `16_COMPONENTS/`)
❌ Нужно больше кода для UI (но это явное преимущество для ИИ)
❌ Меньше разработчиков знают (но это инди-студия, не найм)

## Когда пересмотреть

- Если ИИ начнёт плохо писать vanilla DOM
- Если студия наймёт React-разработчика
- Если появится стандарт web components
- Если bundle size перестанет быть проблемой (сети быстрее)
