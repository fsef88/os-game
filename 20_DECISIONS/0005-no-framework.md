# 0005 — Не использовать фреймворки (Vue, Svelte, Solid)

**Дата:** 2026-07-14
**Статус:** Принято

## Контекст

См. `0004-no-react.md` — решение не использовать React. Нужно также решить про другие фреймворки (Vue, Svelte, Solid, Lit).

## Решение

**Не использовать JS-фреймворки вообще.** Только vanilla TypeScript + DOM API.

## Альтернативы

- **Vue** — проще React, но те же проблемы
- **Svelte** — компилируется, но ИИ плохо пишет `.svelte` файлы
- **Solid** — реактивный, но маленькое сообщество, ИИ редко обучен
- **Lit** — web components, нишевая технология
- **Alpine.js** — облегчённый, но всё равно лишний слой
- **Vanilla TS + DOM** — никаких зависимостей

## Почему НЕ фреймворки

1. **Дополнительный слой абстракции** — игра не нуждается в нём
2. **ИИ тратит токены на знание фреймворка** — меньше места для игровой логики
3. **Сложнее отлаживать** — нужно понимать и игру, и фреймворк
4. **Зависимости = риски** — npm-пакет может перестать поддерживаться
5. **Производительность** — фреймворки добавляют overhead
6. **Размер билда** — даже Svelte + Solid > 10 KB

## Допустимые исключения

- **Yandex SDK** — обязателен для монетизации (внешняя зависимость)
- **Vite** — инструмент сборки (dev-time only)
- **TypeScript** — язык, не фреймворк (компилируется, не выполняется)

## Последствия

✅ Полный контроль над кодом
✅ Минимальный bundle
✅ Максимальная скорость работы
✅ Простая отладка (browser DevTools напрямую)
✅ ИИ может писать без специальных знаний фреймворка

❌ Больше boilerplate (но мы делаем переиспользуемые компоненты в `16_COMPONENTS/`)
❌ Меньше абстракций для сложного UI (но для казуалок хватает)

## Когда пересмотреть

- Если казуальный рынок перейдёт на web components
- Если появится фреймворк с **0 KB runtime**
- Если студия наймёт разработчика без опыта vanilla JS
- Если сложность UI превысит 10 000 DOM-элементов
