# 0003 — Использовать SVG вместо Canvas

**Дата:** 2026-07-14
**Статус:** Принято

## Контекст

Нужно выбрать технологию для графики в казуальных играх студии. Требования: масштабируемость, малый размер, лёгкость редактирования, хорошая поддержка ИИ.

## Решение

Использовать **SVG** (inline) для всех игровых ассетов.

## Альтернативы

- **Canvas 2D** — быстрее для большого количества объектов, но ИИ хуже пишет Canvas-код, и арт сложнее менять
- **WebGL** — для 3D и сложных эффектов, overkill для казуалок
- **PNG спрайты** — большой размер, нет масштабируемости, нужен спрайтшит
- **CSS shapes** — ограниченная выразительность
- **Three.js** — для 3D, не нужно для merge/clicker
- **Phaser/PixiJS** — обёртки над Canvas/WebGL, добавляют зависимость

## Последствия

✅ ИИ отлично генерирует SVG (стандарт W3C)
✅ Масштабируется на любые разрешения (vector)
✅ Малый размер для простых иконок
✅ Inline — можно стилизовать через CSS
✅ Анимации через CSS/SMIL
✅ Игрок может увеличить — качество не теряется

❌ Медленнее Canvas при > 100 объектов на сцене
❌ Сложные эффекты (blur, glow) — нагрузка на CPU
❌ Анимация большого количества SVG = тормоза

## Когда пересмотреть

- Если потребуется 3D графика
- Если будет нужно > 200 одновременно движущихся объектов
- Если Canvas-нативный API станет стандартом для казуалок
